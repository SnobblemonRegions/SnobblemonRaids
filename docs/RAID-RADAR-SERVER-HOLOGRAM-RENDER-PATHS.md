# Server-driven 3D Raid Radar

Research target is Minecraft Java 1.21.1 with Cobblemon 1.8.2, Polymer 0.9.19, and Iris with Complementary. The design goal is real terrain relief for players who already have Cobblemon, using a server-delivered resource pack in place of an extra radar mod.

## Reuse Cobblemon's animated model renderer

A generic Bedrock model is the best candidate. The resource pack would contain a model of the projector and a grid of columns, each with its own bone. The server would send height bands as numeric animation variables. The existing Cobblemon client would stretch the columns to match the terrain. A separate parent bone can tilt the map while the compass remains level. The player marker, raid beacon, and a fixed number of route dots could also be bones. Arbitrary text can use a few vanilla text displays. [Cobblemon model repository](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/client/render/models/blockbench/repository/VaryingModelRepository.kt) · [Bedrock bone animation implementation](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/client/render/models/blockbench/bedrock/animation/BedrockAnimation.kt)

The installed Cobblemon 1.8.2 JAR contains `GenericBedrockEntity`, `SpawnGenericBedrockPacket`, the generic model renderer, and the animation packet handler. The handler evaluates packet expressions in the entity's animation state. The installed bone evaluator reads that same runtime to resolve position, rotation, and scale. The bundled generic models use `bedrock/generic/{models,posers,variations,animations}`, and the renderer uses the standard entity cutout path with resource-defined material layers. The headless diagnostic in `validation/radar/out/server-hologram-research` ran the installed MoLang runtime. It assigned two heights, changed the first in a subsequent evaluation, and read both the new value and the expected scale of `0.181`. This verifies the expression path separately from model loading and in-game rendering. [Generic entity source](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/entity/generic/GenericBedrockEntity.kt) · [Animation packet](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/net/messages/client/animation/PlayPosableAnimationPacket.kt) · [Client packet handler](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/client/net/animation/PlayPosableAnimationHandler.kt)

Send spawn and update packets to the viewing player, with the model and material assets loaded before opening the hologram. A packet-only instance would avoid registering another entity for world ticking. Verify that the exact spawn path can initialize the model, receive the first height update, avoid interfering with targeting, and cleanly remove itself. Use the existing loaded-chunk terrain snapshots, update height bands only when they change, and send marker positions separately. The asset pack can also provide the held tech compass. Players who decline the pack can use the flat radar.

## Movement and shader compatibility

A world-space projector anchored where the player opens it is the simplest first test. It gives true parallax as the player looks around and needs no stream of camera-position updates. The installed generic entity uses the base entity movement path. Its bone evaluator exposes two components of the camera quaternion. Those components alone do not establish a complete camera pose or camera position. A follow mode could use sparse server pose updates and interpolate the root bone between them in MoLang. Test tracking error while turning and walking, including under latency, before comparing the result with the current companion's camera-relative renderer. [Bedrock bone animation implementation](https://gitlab.com/cable-mc/cobblemon/-/raw/main/common/src/main/kotlin/com/cobblemon/mod/common/client/render/models/blockbench/bedrock/animation/BedrockAnimation.kt)

Use ordinary entity materials and test the cutout wire texture, emissive layer, and terrain depth with Complementary enabled. Iris documents that an active shader pack ignores custom core shaders supplied by resource packs. The model approach uses the renderer already provided by Cobblemon, so it avoids that specific conflict. Its lighting and transparency still need in-game verification. [Iris 1.21.1 compatibility note](https://raw.githubusercontent.com/IrisShaders/Iris/1.21.1/docs/development/compatibility/core-shaders.md)

## Alternatives and estimated traffic

| Approach | Terrain render objects per viewer | Estimated movement updates per second at 10 Hz |
| --- | ---: | ---: |
| One vanilla display per cell, 32×32 grid | 1,024 | 10,240 |
| Vanilla item displays using 2×2 model tiles, 16×16 grid | Up to 64 | Up to 640 |
| One Cobblemon terrain model, 16×16 grid | 1 | 10 |

This comparison assumes independent pose updates for each object. At an illustrative 40 bytes per update, that is about 410 kB/s, 26 kB/s, and 0.4 kB/s per viewer, respectively, before compression and excluding labels and terrain. Stationary placement eliminates steady pose traffic. The existing analysis in `validation/radar/out/server-hologram-budget.json` estimates roughly 2.5 kB of animation-packet body for 256 height assignments, or 10.4 kB for 1,024. At a ten-second refresh interval, those average about 0.25 and 1.04 kB/s of terrain data per viewer before compression and framing. These are analytical estimates. Entity count and payload size cannot predict client frame time, particularly with MoLang evaluated across hundreds of bones and multiple material passes.

- **Vanilla model tiles.** Polymer virtual entities can show a model only to selected players, and vanilla display transforms can move and scale it. With four relative height levels in a 2×2 tile, subtracting the minimum leaves 175 patterns. Reusing quarter turns reduces those to 46 prebuilt models. A tile's placement supplies its base elevation. Steep tiles need quantization or subdivision. This is a reasonable fallback if the Cobblemon model route fails, especially for a stationary display. Mounting multiple displays on one anchor may share position updates, but passenger attachment alone does not inherit a complete model transform. [Polymer virtual entities](https://polymer.pb4.eu/latest/polymer-virtual-entity/basics/) · [Mojang display transforms](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-19-4) · [Mojang teleport interpolation](https://feedback.minecraft.net/hc/en-us/articles/19703470383757-Minecraft-Java-Edition-1-20-2)
- **Stacked transparent vanilla maps.** One transparent contour map per elevation could provide detailed planes with very few objects. The exact 1.21.1 bytecode shows why the straightforward approach fails at compass scale. `ItemFrameRenderer` draws the live map, but ordinary item displays use the item model. `BlockAttachedEntity.setPos` quantizes frame positions to block coordinates, and frame orientation lacks the display entity's affine transform. Teleporting those frames is therefore a poor basis for tightly spaced, tilted layers. [Image2Map's working vanilla map-frame display](https://github.com/Patbox/Image2Map)

## Prototype acceptance

1. Load a pack with a four-column generic model on the existing Cobblemon client. Change a height with the server animation packet and verify visible deformation. Test spawn, cleanup, and player-only visibility.
2. Try a stationary 16×16 map using the same meadow fixture. Test with Iris and Complementary active. Verify the level compass, tilted terrain, readable markers, and pack-decline fallback.
3. Measure frame time, server tick time, and actual packet bytes with the radar open and closed. Compare several simultaneous viewers, then test a following version at typical and elevated latency. Increase resolution only if the measurements leave room.

## Stationary prototype result

The model rendered live meadow relief with Cobblemon 1.8.2 and Complementary Unbound r5.1.1. The four-column check visibly changed a column on the existing entity. The full run sampled 256 loaded heights and used an estimated 2,483-byte animation packet body. See the [prototype instructions and measurements](../validation/radar/server-hologram-prototype/README.md).
