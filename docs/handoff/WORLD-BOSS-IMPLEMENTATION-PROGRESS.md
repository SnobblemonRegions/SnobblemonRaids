## Implemented

- `DurableSavedData`: explicit critical writes serialize a complete compressed NBT generation, force the temporary file and require atomic replacement. Autosave uses the same protected writer. Failure retains dirty intent; there is no unsafe rename fallback. This is not a universal hardware/power-loss guarantee.
- `RaidPlayerRecords` + `PointCreditReceipt`: payout promises and credited amounts are stored alongside balances. A staged batch is persisted before publishing changes. Replay does not duplicate credit; balance-cap remainder is retained and claimable. Corrupt receipt data preserves balances/raw evidence and blocks new keyed settlement. Unreadable existing record files cannot silently become new payable empty accounts.
- Startup record initialization is idempotent and happens before credit mutations. This addresses an additional source-discovered ordering issue: the existing world boss startup callback precedes the ordinary player-record restoration listener. A resumed payout must not use an empty LIVE map, and the later normal listener must not reset newly settled balances. The SavedData mirror is retained during initialization.
- World boss recipient/amount plan freezes before first credit. The paid marker follows durable credit/receipt settlement. Interrupted settlement retries rather than abandoning a zero-health event. Optional listener payloads are immutable; Worldheart grants and new-event blessing bounds join the mandatory same-generation victory promise. Full snapshots and cumulative payout promises now join the checksummed write-ahead journal described below; full-server backup orchestration and compact attendance history remain separate work.
- Encounter damage validates both encounter and owning boss IDs. Old callbacks cannot damage a new World Pool. A new event waits for previous duels to finish; orphan/timeout cleanup continues after an event ends.
- Cleanup only targets tagged world boss showpieces near the old center, not every ordinary raid boss in that volume.
- `WorldBossAdmission`: live 50-slot reservation cap, FIFO ready queue, native attempts paced to one per 250 ms without catch-up bursts, generation tokens, idempotent release/refusal, reserved breathers, explicit pause/resume and cooldown-preserving admission. Ward-only breather reconstruction remains separately bounded to two per tick.
- Pause removes gathered/waiting entries and suppresses re-entry after an active duel finishes. Event-scoped pause intent persists. Manual resume cannot bypass the 15-second cooldown. Queue/breather status and clickable Pause/Resume messages are present. Pause save failure is reported; a failed resume retains pause.
- First/between-duel healing uses admitted Pokemon UUIDs and current party ownership, avoiding a stale whole-party replacement. HP/PP/status/faint recovery delegates to Pokemon.heal after valid admission/cleanup. The actual Cobblemon 1.8.2 bytecode confirms full HP, move-set healing, status clearing and faint-timer reset when the healing event is not cancelled. Other mods can cancel that hook; exact-modpack healing behavior still requires live verification.
- Invalid persisted world boss state is quarantined and preserved. Nonfinite health/contributions are rejected. Restored zero-health states can complete settlement.
- `/cr worldboss claim` retries retained cap-overflow points. `/cr worldboss pause` and `resume` are player controls. `/cr worldboss test start` is operator-only; test outcomes issue no live points or external outcome callbacks. Forced wins refuse ordinary live events. Natural damage at/after the current deadline is ignored.
